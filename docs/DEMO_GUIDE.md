# 데모 가이드

면접 때 화면 공유로 보여줄 시연 시나리오. 각 시나리오는 **30~60초** 안에 끝나도록.

## 시나리오 1 — 비교표 (메인 데모)

**흐름**:
1. 메인페이지 → "결제·정산 비교 보기" 버튼 클릭
2. 5개 비교축 × 4개사 그리드 노출
3. **"토스 / 동시성 제어" 셀 클릭** → 사이드 패널에 인용문 + 원문 링크
4. 회사 토글로 "쿠팡" 끄기 → 표가 즉시 좁아짐

**한 줄 멘트**:
> "결제 시스템 동시성을 토스는 멱등키, 카카오페이는 낙관적락+이벤트소싱, 우아한형제들은 분산락으로 푼 게 한눈에 보입니다. 셀마다 원문 인용까지 같이 봅니다."

## 시나리오 2 — 챗봇 (RAG)

**흐름**:
1. /chat → 추천 질문 "Outbox 패턴을 실제로 도입한 한국 회사 사례는?" 클릭
2. 스트리밍 답변 + 우측 사이드바에 [1][2][3] 인용 카드
3. 인용 카드 클릭 → 원문 게시글 열림

**한 줄 멘트**:
> "비교축으로 안 잡히는 long-tail 질문은 챗봇이 인덱싱된 본문에서 직접 찾아 답합니다. 답변에 [n] 인용을 강제해서 환각을 차단합니다."

## 시나리오 3 — 검색 (BM25 + vector hybrid)

**흐름**:
1. /search → "Saga 보상 트랜잭션" 검색
2. 결과 카드들 → 회사명·날짜·점수
3. 도메인 필터 "결제·정산"으로 좁히기

**한 줄 멘트**:
> "키워드 + 벡터 검색을 RRF로 머지합니다. 외부 ES 없이 Postgres 안에서 다 처리해서 운영비를 낮췄습니다."

## 시나리오 4 — 운영 관점 (Bonus)

운영 데이터를 보여주고 싶을 때만:
```sql
SELECT day, model, sum(cost_usd)::numeric(10,4)
FROM llm_costs
WHERE day >= CURRENT_DATE - INTERVAL '7 days'
GROUP BY day, model
ORDER BY day DESC;
```
> "프롬프트 캐싱으로 시스템 프롬프트 input 토큰을 90% 절감했고, 일일 한도를 환경변수로 막아둡니다."
